How a question becomes an answer

The agentic RAG path in nextjs-rag-boilerplate, as of v0.24.1. A planner model chooses what to search for. The code decides when it has to stop, what counts as evidence, and when to refuse.

The search loop

The planner sees the question, the last 4 chat turns, and what earlier searches found. It rewrites follow-ups into full searches, so "what about carrying it over?" becomes "carrying over annual leave". With adaptive planning on, a standalone question skips the planner and gets one plain search.

4

Keep only strong evidence

Results are merged and duplicates dropped. Anything below the relevance pass mark is thrown out. The pass mark rises with each extra text search, because more tries give more chances to find an irrelevant passage by luck. Reading a figure doesn't count, so it can't push out the figure it read.

6

Write the answer

The chat model streams an answer from the kept passages only, citing each one as [1], [2] and so on. It also gets what the planner took a follow-up to mean, and what any figure read showed, labelled as a reading and cited as the figure.

7

Check the citations

One more model call checks whether each source really supports its sentence. Unsupported sentences are removed and the corrected answer replaces the streamed one. It runs once and never redrafts. If the check fails, the answer stays as it was.

What the planner can't do

  • Widen its access. The server fixes which user and which knowledge bases are allowed. The planner only supplies a search query, plus a figure ID for read_figure, which the server checks.
  • Loop forever. Every limit is checked before the next call, and a slow call, a search included, is cut off when time runs out.
  • Answer without evidence. Refusing is a code path around the loop. It isn't an instruction the model can be talked out of.
